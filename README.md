# Video Prompt Director v2.1.0

**이야기는 짧게 말하고, 연출 설계는 AI에게 맡기세요.**

“비 오는 항구의 낡은 배를 쓸쓸하게 보여줘”처럼 말하면, AI가 장면의 시작과 끝, 카메라, 빛, 재질, 레퍼런스 준비물을 설계하고 영상 생성용 문구로 정리합니다. 카메라 용어를 먼저 공부할 필요는 없습니다.

> 이 저장소는 AI가 읽는 **스킬 지침과 사용 매뉴얼**입니다. 영상 생성 프로그램이나 모델을 포함하지 않습니다. 프롬프트 작성만으로 이미지·영상 파일이 자동 생성되지는 않습니다.

## v2.1 핵심 변경: 상세 연출을 실제 프롬프트에 남깁니다

v2.0에서 연출을 내부적으로 생각하더라도 최종 문장이 사건 요약처럼 짧아질 여지를 수정했습니다. 이제 기본 출력은 **촬영 상세본**입니다. 사용자에게 설명하는 글은 짧게 유지해도 생성용 본문의 유용한 촬영 정보까지 줄이지 않습니다.

- **공통 룩 / 공간·연속성 / 시간별 컷 / 필요한 음향·제약**으로 작성합니다.
- 각 컷의 구도, 카메라, 초점, 실제 변화, 끝 상태를 최종 영문 본문에서 확인합니다.
- 빛·질감·재질 반응을 'natural daylight / realistic movement'라는 말로 대신하지 않습니다.
- 기본 단어 수 상한과 디테일 개수 제한을 제거했습니다. 길이 자체보다 필요한 촬영 정보가 있는지를 봅니다.
- 카메라가 고정이어도 묘사는 풍부할 수 있습니다. 디테일을 늘리기 위해 새 사건이나 불필요한 카메라 효과를 추가하지 않습니다.
- 모델의 실제 제한이 확인되면 상세본을 기준으로 별도 실행본을 줄여 만듭니다. 사용자가 짧게 요청하면 그 요청을 따릅니다.
- 사진을 아직 못 봤더라도 조건부 상세 연출안은 준비할 수 있지만, 사진 검토 완료나 실행 준비 완료로 표시하지 않습니다.

[연못·강아지 상세 출력과 회귀 기준](detail-regression.md)에서 이번에 점검하는 수준을 확인할 수 있습니다. 실제 영상 생성 결과와는 구분합니다.

## 빠르게 시작하기

스킬을 설치하거나 아래의 '일반 채팅 AI에서 사용하기'를 따라 문서를 제공한 뒤, 이렇게 말해보세요.

```text
video-prompt-director를 사용해줘.
비 오는 새벽 항구에 낡은 어선이 묶여 있는 10초 영상이야.
사람은 없이, 조용하고 쓸쓸하게.
연출은 네가 설계하고 필요한 레퍼런스 이미지 프롬프트도 같이 줘.
Kling에서 쓸 예정이야.
```

보통 다음을 받습니다.

1. **연출 방향:** 어떤 느낌을 어떤 화면으로 만들지
2. **장면 설계:** 시작 → 눈에 보이는 변화 → 끝 상태
3. **레퍼런스 준비:** 이미지가 필요한 이유, 장수, 역할, 이미지 생성용 문구
4. **영상 생성용 문구:** 실제로 복사해서 넣을 문구
5. **사용 순서:** 어떤 이미지를 먼저 만들고 어디에 넣을지, 아직 확인하지 못한 조건

한 가지 좋은 방향을 기본으로 제안합니다. 여러 대안을 원하면 따로 요청하세요.

## v1에서 무엇을 바꿨나요?

기존 지침은 '항목을 잘 정리하라'는 요구에 비해 좋은 연출을 만들어내는 절차가 부족했습니다. 또 이야기 보존을 강조하다가 촬영에 필요한 세부까지 추가하지 못하게 만들 여지가 있었습니다.

| 이전 설계의 약점 | v2의 변경 |
| --- | --- |
| 원안에 없는 것을 전부 금지하는 넓은 제한 | 이야기·정체성은 지키되 구도·빛·재질·속도는 AI가 설계 |
| 대상·카메라·분위기 항목 나열 | 시작 화면, 행동의 진행, 마지막 화면을 먼저 구성 |
| '영화처럼'이라는 추상 표현 | 무엇에 빛이 닿고, 어떤 힘 때문에 무엇이 움직이는지 구체화 |
| 레퍼런스 필요 여부 안내 위주 | 필요한 이미지의 역할·구도·사용 컷·준비 상태·생성 문구까지 제공 |
| 텍스트→영상과 이미지→영상의 차이가 약함 | 이미지가 있으면 외형을 지키고 움직임을 중심으로 문구 작성 |
| 간단한 모순 검사 | 8개 기준의 자체 검수와 치명적 오류 우선 수정 |
| 참고 예시의 좋은 요소를 막연히 권장 | 원문을 분석하고 좋은 원리와 잘못된 지시를 분리 |

**실제 영상 품질 개선을 검증한 벤치마크는 아닙니다.** v2는 설계 절차와 프롬프트의 구체성을 개선한 버전이며, 결과 영상은 사용하는 모델과 입력 이미지에 따라 달라집니다.

## 설치와 업데이트

### 1. 파일 받기

GitHub 상단의 **Code → Download ZIP**으로 내려받아 압축을 풀거나 Git으로 저장소를 복제하세요. 실행 파일이나 별도 패키지 설치는 필요 없습니다.

실행에 필요한 네 파일은 항상 함께 보관합니다.

```text
video-prompt-director/
  SKILL.md
  directing-guide.md
  reference-analysis.md
  detail-regression.md
```

- `SKILL.md`: AI가 따르는 핵심 진행 순서
- `directing-guide.md`: 연출 선택법, 완성형 제품 예시, 품질 검수
- `reference-analysis.md`: 항구·어선 레퍼런스 재분석과 정리된 두 컷 예시
- `detail-regression.md`: 빈약한 요약문을 막는 출력 기준과 연못·강아지 적용 예시
- `README.md`: 지금 읽는 사용자 매뉴얼. 스킬 실행 폴더 밖에 둬도 됩니다.

**이전 버전 사용자는 SKILL.md만 바꾸지 말고 세 보조 문서도 함께 넣으세요.** 예전 파일은 다른 위치에 백업한 뒤 교체하고 새 대화에서 불러오는 편이 좋습니다. 자동 인식 여부는 사용하는 앱에서 확인하세요.

### 2. Aside에서 사용하기

Aside 계정의 사용자 스킬 폴더 안에 위 네 파일을 넣습니다.

```text
<Aside 계정 폴더>/skills/user/video-prompt-director/SKILL.md
<Aside 계정 폴더>/skills/user/video-prompt-director/directing-guide.md
<Aside 계정 폴더>/skills/user/video-prompt-director/reference-analysis.md
<Aside 계정 폴더>/skills/user/video-prompt-director/detail-regression.md
```

Aside가 스킬을 읽을 수 있도록 요청합니다.

```text
video-prompt-director 스킬을 읽고 사용해줘.
설치된 SKILL.md 제목이 v2.1.0인지 확인하고,
directing-guide.md와 detail-regression.md도 읽어줘.
줄거리 요약이 아니라 촬영 디테일이 담긴 상세 프롬프트로 작성해줘.
```

### 3. 일반 채팅 AI에서 사용하기

사용자 지정 스킬 설치 기능이 없어도 됩니다. 위 네 문서를 대화나 프로젝트에 첨부하고 다음처럼 요청하세요.

```text
첨부한 SKILL.md를 작업 지침으로 사용해줘.
directing-guide.md와 detail-regression.md를 읽고,
최종 생성 문구에도 구도·초점·빛·재질·행동·끝 상태를 남겨줘.
레퍼런스를 분석할 때는 reference-analysis.md의 분석 방식을 참고하되,
그 문서의 색감·안개·핸드헬드를 모든 영상에 복사하지 마.
내 짧은 아이디어를 바로 사용할 수 있는 영상 프롬프트로 만들어줘.
```

Codex나 Claude Code 등 파일을 읽을 수 있는 도구에도 같은 방식으로 폴더를 지정할 수 있습니다. 자동 스킬 설치 위치와 호출 방식은 도구별 안내를 따르세요. 이 저장소는 각 앱의 모든 버전에서 자동 인식된다고 보장하지 않습니다.

## 최소한 무엇을 말하면 되나요?

**무엇을 보여주고 싶은지**만 말해도 시작할 수 있습니다. 아래 정보는 아는 만큼만 보태세요.

| 정보 | 평소 말로 쓰는 예 |
| --- | --- |
| 대상과 행동 | 고양이가 상자에 들어가 앉아 |
| 용도 | 화장품 광고 / 여행 릴스 / 짧은 영화 / 설명 영상 |
| 분위기 | 차분하고 고급스럽게 / 밝고 장난스럽게 |
| 길이·비율 | 10초, 세로 영상 |
| 반드시 지킬 것 | 로고 그대로, 사람 없이, 컷 전환 없이 |
| 사용 도구 | Kling, 또는 아직 정하지 못함 |

길이·비율을 말하지 않으면 짧은 8–10초·16:9를 기획상 가정할 수 있습니다. **생성기가 그 길이·비율을 지원한다는 뜻은 아닙니다.** 중요한 사정만 짧게 질문하고 나머지 연출은 AI가 정합니다.

## 실제 작업 순서

### 이미지 없이 시작할 때

1. 한두 문장으로 아이디어를 말합니다.
2. AI가 텍스트만으로 충분한지 판단합니다.
3. 충분하다면 영상 문구를 생성기에 넣습니다.
4. 구도나 정체성을 고정하는 데 이미지가 도움이 된다면 이미지용 문구를 먼저 사용합니다.

### 첫 프레임 이미지를 만들 때

'첫 프레임'은 **영상이 시작할 때의 한 장면**입니다.

1. AI가 준 이미지용 문구를 이미지 생성기에 넣습니다.
2. 만들어진 이미지의 형태·구도·빛을 확인합니다.
3. 확인한 이미지를 AI에 보여주고 '이 이미지 기준으로 움직임을 맞춰줘'라고 합니다.
4. 영상 생성기의 첫 프레임 입력칸에 그 이미지를 넣습니다.
5. 이미지→영상용 문구를 넣고 생성합니다.

이미지 문구를 받았다는 것은 이미지 파일을 준비했다는 뜻이 아닙니다. 이미지는 따로 생성하거나 준비해야 합니다. 사용하는 AI가 이미지 생성 도구를 갖고 있다면 '이 문구로 이미지도 만들어줘'라고 별도 요청할 수 있습니다.

### 특정 인물·실물 제품을 유지할 때

원본 이미지를 제공하는 것이 우선입니다. '내 향수병이랑 똑같이'만으로 AI가 실제 병과 로고를 알 수는 없습니다. 원본이 없다면 촬영 방향까지는 설계할 수 있지만 정확한 외형을 고정한 최종 프롬프트는 **원본 대기**로 표시합니다. 로고·정확한 글자는 나중에 편집으로 합치는 편이 필요할 수 있습니다.

## 레퍼런스는 몇 장이 필요한가요?

정해진 정답 장수는 없습니다. **가장 적은 이미지로 필요한 것만 고정**합니다.

| 이미지 역할 | 언제 유용한가 | 주의점 |
| --- | --- | --- |
| 정체성 기준 | 같은 얼굴·옷·제품·배를 반복 사용 | 첫 구도까지 고정하는 이미지와 역할이 다름 |
| 장면 구도/첫 프레임 | 원하는 배치·빛·시작 위치가 중요 | 행동이 이미 끝난 모습으로 만들지 않기 |
| 스타일 참고 | 색감·재질·화풍을 맞춤 | 해당 모델이 스타일 참조를 지원하는지 확인 |
| 끝 프레임 | 정해진 마지막 화면이 중요 | 지원되는 모드에서만 사용, 중간 연결은 보장되지 않음 |

AI는 R1, R2처럼 이미지에 이름을 붙여 역할과 사용 컷을 설명합니다. 이는 준비물을 구분하는 이름이며, 생성기에 그대로 입력하는 만능 명령어가 아닙니다. 실제 입력칸이나 참조 문법이 확인되지 않았다면 임의로 만들어 쓰지 않습니다.

## 용도별 복사해서 쓰는 요청

### 영화적인 풍경
```text
비 오는 항구의 낡은 배를 쓸쓸하게 보여줘. 10초, 사람 없이.
새 사건을 만들지 말고 공간·빛·움직임으로 분위기를 살려줘.
필요한 레퍼런스와 영상 프롬프트까지 한 번에 줘.
```

### 제품 광고
```text
이 제품 사진을 기준으로 차분하고 고급스러운 8초 광고를 설계해줘.
제품 형태와 로고는 유지해. 빛이 표면에 어떻게 보일지까지 설계하고,
과한 카메라 움직임보다 제품이 잘 읽히게 해줘.
```
사진은 실제로 첨부해야 합니다. 첨부하지 않았으면 준비물부터 안내합니다.

### 밝은 코미디
```text
고양이가 택배 상자를 보고 다가갔다가 안에 들어가 앉는 12초 영상.
밝고 귀엽게, 원테이크로. 새 등장인물이나 다른 사건은 추가하지 마.
동작과 잠깐의 멈춤으로 재미를 만들어줘.
```

### 기존 이미지에 작은 움직임만
```text
첨부한 사진의 인물과 옷은 그대로 둬.
5초 동안 고개만 살짝 돌리게 하고 카메라는 완전히 고정해.
사진과 충돌하는 설명은 넣지 말고 이미지→영상 프롬프트만 줘.
```

### 좋은 프롬프트에서 방법 배우기
```text
이 레퍼런스 프롬프트를 먼저 분석해줘.
무엇이 시선을 끌고, 시간에 따라 무엇이 바뀌며,
빛·재질·물리 반응을 어떻게 설계했는지 설명해줘.
오류와 반복은 걸러내고, 내 주제에 맞는 원리만 적용해줘.
```

## 결과가 아쉬울 때 이렇게 말하세요

'더 고퀄로'보다 **유지할 것 + 바꿀 것**을 말하면 수정 방향이 뚜렷해집니다.

- “색감은 좋아. 카메라만 고정하고 대상의 작은 움직임이 보이게 해줘.”
- “제품 모양이 달라졌어. 이동 각도를 줄이고 같은 외형을 유지하는 쪽으로 고쳐줘.”
- “평범한 스톡 영상 같아. 형용사를 늘리지 말고 이 장면만의 빛·재질·끝 상태를 다시 설계해줘.”
- “초점이 계속 헤매. 한 번 맞춘 뒤 고정하게 해줘.”

가능하면 실제 결과 이미지나 영상과 사용한 문구를 함께 주세요. 영상이 제공되지 않았다면 AI는 가능한 원인을 추정할 뿐 실제 원인으로 단정하지 않도록 설계했습니다.

## v2.1 점검 범위

이번에는 조건 보존만 확인하지 않고 **연못·강아지 사례의 영문 상세 프롬프트를 실제로 작성해** 최종 문장 속 촬영 정보를 확인했습니다. 적용 출력과 검수 반영본을 [detail-regression.md](detail-regression.md)에 실었습니다.

- 15초·네 숏의 사건 순서와 반대편 둑의 공간 연결
- 컷별 구도·카메라·초점·물리 반응·끝 상태가 최종 본문에 남는지
- 흰 털·은발·흰 의상의 밝은 부분과 수면 반사를 구체화하는지
- 정지 제품 사례에서 디테일을 위해 카메라·병을 임의로 움직이지 않는지
- 명시적인 80단어 제한에는 68단어 단축본으로 대응하는지
- 실제 사진을 못 본 사실과 실행 모델 미확인 상태를 숨기지 않는지

이것은 텍스트 출력 점검이며 실제 영상 생성이나 영상미 비교 실험은 아닙니다. 새 버전이 모든 모델에서 항상 더 좋은 영상을 만든다는 보장은 하지 않습니다.

## v2.0 점검 이력

배포 전 파일 형식·문서 연결을 확인하고, 별도 AI 검토자가 세 가지 입력에 지침을 적용해 텍스트 결과를 점검했습니다.

| 입력 | 점검한 결과 |
| --- | --- |
| 밝은 고양이 코미디, 12초 원테이크 | 한 컷 유지, 발견→접근→상자 안에 앉기의 순서, 밝은 빛과 고정 구도 선택 |
| 정확한 실물 향수 광고, 사진 없음 | 가짜 제품 외형을 만들지 않고 원본 요청 및 레퍼런스 대기 처리 |
| 기존 인물 사진에서 고개만 회전, 사진 없음 | 사진을 본 척하지 않고 카메라 고정 조건을 유지한 동작 계획만 제시 |

검토에서 지적된 '없는 실물 원본을 합성 이미지로 대체할 여지'는 명시적으로 금지하도록 보강했습니다. 이 점검은 소수의 텍스트 적용 사례이며, 자동 회귀 테스트나 실제 영상 생성 비교 실험은 아닙니다.

## 한계

- 스킬은 생성 모델 자체를 개선하지 않습니다. 같은 문구라도 모델·버전·설정·입력 이미지에 따라 결과가 달라집니다.
- 복잡한 손 동작, 정확한 글자, 여러 컷의 동일 인물, 정밀한 시간 제어는 실패할 수 있습니다.
- 지원되지 않는 오디오·다중 이미지·끝 프레임 기능은 프롬프트만으로 활성화할 수 없습니다.
- 원테이크 조건이 없고 컷 제어가 어렵다면 각 컷을 따로 생성해 편집하는 편이 낫습니다.
- 유료 생성, 이미지 준비, 게시 등의 실제 실행은 별도 작업입니다. 문구 작성 완료와 영상 제작 완료를 구분합니다.
